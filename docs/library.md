# Личная библиотека

`/library` показывает только книги текущего аккаунта, включая статус удаления.
Пустая библиотека — нормальное состояние. Пагинация: 20 записей по умолчанию,
`size` от 1 до 50, `page` от 0 до 10000; несуществующая страница после первой — 404.
Порядок: `created_at DESC, id DESC`, включая стабильный порядок при одинаковой дате.
Новые загрузки между запросами могут сдвигать страницы: snapshot pagination не обещана.

Карточка `/library/books/{id}` содержит название, автора, формат, размер исходника,
дату UTC и состояние. Изменение названия/автора и подтверждение удаления используют
отдельные GET-формы и POST с CSRF. Название обязательно, автор необязателен;
оба ограничены 200 Unicode code points, управляющие символы запрещены, края обрезаются.
Данные выводятся через экранирование Thymeleaf, HTML в метаданных не исполняется.

## Доступ и конкурентные изменения

Каждый сценарий сервиса получает владельца из `AccountPrincipal.accountId` и заново
проверяет существование аккаунта, username, роль и все флаги доступа. ID владельца
из HTTP не принимается. Администратор использует свою библиотеку; чужой ID и
отсутствующий ID дают одинаковый 404. Сессия удалённого или переименованного аккаунта
не становится сессией нового владельца username.

Repository ограничивает SQL владельцем до чтения/блокировки. Запись берёт
`PESSIMISTIC_WRITE`, сравнивает присланную версию и использует JPA `@Version`.
Два редактирования одной версии не перезаписывают друг друга: проигравшее получает 409.
Форма сохраняет правки пользователя, показывает актуальные данные и предлагает
явно повторить сохранение. Смена владельца, формата, исходника, состояния или роли
через форму запрещена allowlist binding; entity не передаётся в model.

## Схема и жизненный цикл

V5 добавляет `books`: владелец FK на users, title/author, EPUB/TXT, состояние,
размер 1..10485760 байт, SHA-256 и непрозрачный уникальный UUID хранения,
время создания и версия. Индекс обслуживает owner/order; уникальность
`(owner_id, source_sha256)` распространяется и на `DELETING`.
Одинаковый исходник у разных владельцев допустим. Путь и fingerprint не выводятся в UI.
Удаление аккаунта с книгами блокируется FK, автоматического каскадного удаления нет.

Новая книга создаётся доверенным ingestion-кодом в `PROCESSING`. Публичного
create/READY endpoint нет. Только успешная проверка исходника в #22 переводит
её в `READY`. Загрузка, проверка файлов и атомарное резервирование квот реализованы в #22;
production-данные или демонстрационные книги автоматически не создаются.

Редактировать метаданные можно только в `READY`. `PROCESSING` доступна для просмотра
метаданных и отмены через удаление. Подтверждённый POST переводит запись в `DELETING`:
карточка и изменения сразу закрываются, в списке остаётся строка состояния без ссылки.
Повторный подтверждённый POST безопасен. UUID/размер/fingerprint остаются в БД до
завершения cleanup; это предотвращает потерю ссылки и преждевременное освобождение
квоты. Ошибка версии требует повторного подтверждения. GET ничего не удаляет.

**Граница #19:** физическое удаление файлов/возобновление cleanup после рестарта реализованы в #22 ([book-files.md](book-files.md));
удаление будущего прогресса и заметок — интеграция #25/#26. Их таблиц/endpoint пока нет.
Нельзя считать `DELETING` доказательством удаления данных с диска или завершённой квоты.
#19 остаётся открытой до проверки связанного удаления после этих задач.

## Миграция и восстановление

Перед применением V5 сделайте согласованную резервную копию БД. V1–V4 не меняются;
V5 не переносит права и не меняет существующие аккаунты. Откат приложения требует
восстановить совместимую сборку, сохранив новую таблицу; автоматического down SQL нет.
Не удаляйте `books` после появления данных: перед восстановлением БД нужны
согласованные исходники по процедуре #22. Безопасные резервные копии —`database.md`.

## Проверки и пределы

`make check` включает настоящий MVC/JPA/Security на изолированной H2: два пользователя
и администратор, owner404, CSRF, validation, пустое состояние, пагинация,
экранирование, версии, подтверждение и повтор удаления, текущие флаги аккаунта.
`make test-integration` дополнительно запускает `BookPostgresIT`: V5/JPA validate,
реальные ограничения и уникальность, 200 emoji, owner queries и конкурентную запись.
H2 `varchar` считает UTF-16 units; предельная запись 200 astral code points проверяется
на PostgreSQL, а CodePointLength DTO —отдельно. H2 preview этого предела не подтверждает.

WCAG 2.2 A/AA проверяется по изменённым страницам: клавиатура, видимый focus,
label/error ID, 320px, увеличение текста и автоматический axe. Это не утверждение
о соответствии всего сайта; старые главная/формы и ручная проверка screen reader
сохраняют собственные ограничения. Цели производительности из `mvp.md` ещё не измерены.
