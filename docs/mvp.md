# MVP «ДостоRead»

Университетская курсовая третьего курса: личная онлайн-библиотека с загрузкой,
чтением, прогрессом и заметками. Этот документ задаёт проверяемый объём #4,
а не утверждает готовность книжных функций. Приёмочные цели ниже ещё предстоит
подтвердить реализацией и evidence из #19–#29.

Владелец подтвердил EPUB + TXT без DRM/других форматов и лимиты10 МиБ на файл,
100 книг,1 ГиБ исходников на пользователя. Email обязателен, роли единые users,
Admin не имеет доступа к чужим личным данным — ранее согласованные решения.
Остальные ограничения и критерии ниже — технические решения этой спецификации;
их утверждение происходит при review/слиянии PR #4. Стек Java/Spring/Thymeleaf/
JPA/PostgreSQL и TypeScript/Webpack сохраняется. Деплой и публикация образов
не являются частью результата.

## Сценарий пользователя

1. Зарегистрироваться с уникальными username/email, войти.
2. Загрузить поддерживаемую книгу; увидеть обработку/ошибку либо готовую книгу.
3. Найти её в своей библиотеке, открыть карточку, при необходимости изменить
   название/автора. Список имеет пагинацию и понятное пустое состояние.
4. Открыть читалку: текст, главы EPUB, переход по оглавлению, размер шрифта и
   подгрузка ограниченного фрагмента вместо всего документа в DOM.
5. Сохранить позицию и личную текстовую заметку у этой позиции.
6. Выйти, войти повторно и продолжить с сохранённой позиции; заметка сохраняется.
7. Удалить книгу с подтверждением: она немедленно перестаёт открываться, связанные
   прогресс/заметки удаляются, исходник и служебные файлы очищаются с retry при сбое.

Скачивание собственного исходника входит в файловый сценарий; выдача только
после owner-проверки, с attachment/nosniff/no-store и безопасным filename.
Общий каталог, обмен книгами, подписки, рекомендации, рассылки, OCR, синхронизация
с внешними магазинами и offline/PWA не входят в MVP.

## Форматы и отображение

| Формат | Принимаем | Поведение |
| --- | --- | --- |
| TXT | `.txt`, строгий UTF-8 с допустимым UTF-8 BOM | Простой текст; CRLF/CR приводятся к LF в представлении, исходные байты сохраняются |
| EPUB | `.epub`, EPUB2/3 reflowable с XHTML-текстом и одним package/rendition | Порядок spine, заголовки/абзацы/списки/выделение, оглавление NCX/nav, локальные PNG/JPEG |
| Прочее/защищённое | Не принимаем | Понятный отказ до READY и чтения; защиту не снимаем |

Невалидный UTF-8, NUL/бинарный TXT, пустой текст и повреждённый контейнер
отклоняются. Кодировку TXT не угадываем; пользователю сообщается требование UTF-8.
EPUB проверяется по структуре контейнера/mimetype/container.xml/OPF/manifest/spine,
а не по расширению и заявленному MIME. Fixed layout, DTBook/SVG-only spine,
несколько renditions и публикации без пригодного текстового содержимого
отклоняются как неподдерживаемый вариант. Это ограниченный профиль чтения,
не заявление полной EPUB Reading Systems conformance.

Авторские CSS/шрифты, JS, формы, iframe/object, аудио/видео и активный SVG не
исполняются/не загружаются. Содержимое преобразуется в безопасное представление
приложения; внешний контент не скачивается, внешние ссылки остаются текстом.
PNG/JPEG выдаются через приватный resource handler после проверки владельца;
сырой XHTML/XML из архива не становится страницей origin приложения.
Неподдерживаемые дополнительные медиа помечаются в читалке; у картинок сохраняется
безопасный alt-текст. CSS/типографика приложения имеют приоритет над EPUB-вёрсткой.

DRM/encrypted content отклоняется. Одно наличие encryption.xml не является
доказательством DRM: стандартная font obfuscation описывается тем же файлом
([W3C EPUB3.3](https://www.w3.org/TR/epub-33/#sec-container-metainf-encryption.xml)).
Если защищены только шрифты стандартной obfuscation, книга может читаться со
шрифтами приложения, сами шрифты не загружаются/не декодируются. Неизвестный
алгоритм или шифрование содержимого означает отказ. Это не поддержка DRM.

## Лимиты и обработка

Все размеры бинарные: МиБ=1_048_576 байт, ГиБ=1_073_741_824 байт.

| Ограничение | Значение по умолчанию |
| --- | --- |
| Исходник | >0 и <=10 МиБ; HTTP multipart request <=11 МиБ |
| Книги пользователя | <=100, включая резервируемые/удаляемые записи |
| Квота исходников пользователя | <=1 ГиБ, включая upload reservations и ещё не удалённые файлы |
| EPUB после распаковки, по фактически прочитанным байтам | <=32 МиБ суммарно, <=8 МиБ на entry |
| ZIP entries / отношение распаковки | <=2000 / <=100:1 |
| Растровое изображение | <=16_000_000 пикселей, каждая сторона <=8192 |
| Одновременные загрузки, включая приём тела | <=2 на экземпляр, без бесконечной очереди |
| Временные файлы экземпляра, включая pending cleanup | <=128 МиБ суммарно |
| Приём multipart тела | <=30 секунд с начала обработки запроса |
| Время обработки после получения исходника | <=10 секунд; превышение — контролируемый отказ |
| Фрагмент текста в читалке | <=16_384 Unicode code points за ответ |
| Название / автор | Непустое название <=200 code points; автор необязателен, <=200 |
| Страница библиотеки/заметок | Default20, max50; стабильный порядок createdAt,id |
| Заметка / число заметок | Непустой plain text <=2000 code points; <=200 на книгу |

Квоты проверяются сервером атомарно, включая параллельные загрузки. При этих
defaults лимит100 книг обычно достигается раньше1 ГиБ; политики остаются
отдельными проверками. Одинаковые байты в библиотеке одного владельца не создают
вторую книгу/квоту:409 со ссылкой только на существующую свою READY запись.
Для PROCESSING/DELETING возвращается409 с текущим состоянием, без ссылки чтения
и без новой записи/резерва; после окончательного cleanup файл можно загрузить
снова. Между владельцами данные не переиспользуются и наличие чужого файла
не раскрывается.

ZIP/XML обрабатываются с конечными счётчиками/таймаутами: без рекурсивной
распаковки, traversal, symlinks, внешних DTD/entities, XInclude и сетевых URI.
Нельзя доверять только размерам central directory. Имена/пути из архива не
становятся storage paths; ключи генерирует сервер вне webroot. Обработка потоковая,
не требует постоянного распакованного дерева; временные/производные данные имеют
конечный бюджет в пределах32 МиБ на задачу и удаляются после неё/при сбое.
Постоянного неограниченного per-book cache в MVP нет. Admission-лимит применяется
до multipart разбора, чтобы не создавать неограниченные temp files до controller;
CSRF и аутентификация при этом не ослабляются. Admission slots освобождаются
при завершении запроса/отказе/таймауте; quota/storage reservations — только после
подтверждённого cleanup. Оставшиеся для retry временные файлы продолжают занимать
бюджет128 МиБ; исчерпание бюджета также даёт503 без новой записи/записи файла.
XML/XHTML ограничены глубиной128 и64 атрибутами на узел.
При занятости обоих workers
новая загрузка получает503+Retry-After; это не повод отключать CSRF или rate limits.

Текущие10MB/11MB Spring multipart settings соответствуют первым двум размерам;
книжные квоты, ZIP/media/deadline ограничения реализованы в #22,
контракт/проверки —[book-files.md](book-files.md).
Изменение этих продуктовых limits требует явного обновления спецификации и tests.

## Библиотека, прогресс и заметки

У книги immutable исходник/проверенный формат/content fingerprint. Замены файла
на месте в MVP нет: другой исходник загружается отдельной книгой. Название/автор
редактируются без изменения позиции. Поиск/теги/публичная сортировка/каталог
не обязательны: достаточно своей пагинированной библиотеки.

Позиция не зависит от ширины экрана или размера шрифта: TXT — offset в
нормализованном Unicode-тексте, EPUB — stable spine item и offset в его безопасном
текстовом представлении. Locator связан с fingerprint/версией представления,
проверяется сервером на диапазон и не переносится молча на другое содержимое.
Полная EPUB CFI совместимость не требуется. Заметка привязана к такому locator.

Сохранение прогресса debounce2с и при завершении чтения/уходе со страницы;
изменения отправляются с ограниченной частотой, результат «сохранено» показывается
только после подтверждения сервера. Сеть/401/ошибка не становятся ложным успехом,
несохранённое состояние явно показано, бесконечных retry/offline очередей нет.
Для двух вкладок progress/notes используют server revision: устаревшая mutation
даёт409; клиент предлагает загрузить актуальное состояние либо явно повторить
сохранение после refresh revision. Client timestamp не решает конфликт сам.

## Владение и удаление

Матрица [authorization.md](authorization.md) обязательна: два User и Admin
видят/меняют только свои книги, исходники, ресурсы, прогресс и заметки. accountId
берётся из доверенного principal, актуальный допуск аккаунта и owner проверяются
в service/query до чтения/эффекта. Чужой и отсутствующий private ID дают одинаковый
404. Owner/role из клиента не назначают права. Email остаётся обязательным, но
не подтверждённым; verification/recovery и публичного admin provisioning нет.

Удаление без корзины/undo, после явного подтверждения пользователя. При сбое
storage книга остаётся в состоянии DELETING: закрыта для чтения/mutations,
квота ещё занята, очистка повторяется. Первый DB commit скрывает книгу и удаляет
progress/notes; запись-технический маркер и quota reservation удаляются после
подтверждённого удаления файла. Недостающий при retry файл считается уже удалённым;
повтор операции безопасен, после окончательного удаления item404 допустим.
Нельзя обещать общую DB+filesystem транзакцию или освобождать квоту до cleanup.
Ошибки upload/delete проверяются fault injection в #22; внешняя очередь/новая
инфраструктура для этого не требуются.

## Цели качества и контрольный стенд

Это целевые пороги приёмки #27, а не уже измеренные результаты. Контрольный
стенд: Linux x86_64, Docker Compose app+PostgreSQL с совокупным бюджетом2vCPU/
4 ГиБ RAM и локальным SSD; браузер Chromium отдельным процессом вне бюджета
серверных контейнеров. Версии/CPU/memory limits/данные/команда фиксируются в evidence.
Build и загрузка зависимостей не входят во время runtime-замеров.

Набор:10 пользователей по100 книг; небольшие уникальные синтетические источники
и по одному близкому к10 МиБ EPUB/TXT на владельца;10 заметок на книгу. Перед
замером warm-up, затем не менее100 запросов на сценарий при10 параллельных
пользователях с pacing в пределах rate policy. Nominal запуск не включает
специальные конфликты, превышение admission/rate или fault injection; загрузки
проверяются отдельно с не более2 одновременными задачами. В nominal ожидаются
успешные2xx без потерь: любой неожиданный4xx/429/5xx — провал запуска, а не способ
исключить медленный ответ из статистики.

- p95 списка/карточки <=500мс, фрагмента reader <=1000мс, progress/note mutation
  <=500мс; считать по ожидаемым успешным2xx. Ожидаемые409/429/503 при отдельных
  conflict/overload/fault trials проверяются как отказы, не включаются в latency
  выборку и не отменяют критерий успешности nominal запуска.
- Начальный текст читалки виден <=2с на локальном стенде; DOM/network не содержат
  весь10 МиБ текст. Ingest ограничен10с, превышение не приводит к OOM/потере данных.
- WCAG2.2 A/AA в критическом сценарии: keyboard/focus, labels/errors/status,
  200% text zoom и reflow320 CSS px, scoped axe без необъяснённых serious/critical
  нарушений; ручной screen-reader smoke на доступной паре browser/assistive tech.
  Невыполненная ручная проверка отмечается явно, соответствие всего продукта
  стандарту без аудита не заявляется.
- Backup PostgreSQL+исходников одной согласованной точки с остановкой writes,
  восстановление отдельной пустой копии и проверка книг/позиций/заметок/owner (#28).
  Цель восстановления <=15мин на этом наборе с локального backup; RPO — последний
  проверенный backup, расписание автоматических backups/SLA вне MVP без деплоя.

## Итоговая приёмка и очередь

#19 — модель/metadata/пагинация/owner; #22 — безопасные upload/storage/download/
cleanup/квоты; #23 — TXT/EPUB reader и безопасные ресурсы; #25/#26 — позиции/заметки/
конфликты; #27/#28/#29 — сквозные проверки, измерения, восстановление и документация.
Основы #17/#18 уже готовы; их реальные owner/file критерии закрываются evidence
соответствующих функций, без циклического ожидания закрытого umbrella issue.

Итог: registration→login→upload обоих форматов→library→read→save position/note→
logout→login→continue, затем restart и повторная проверка, удаление и restore.
Отдельно: второй User/Admin, foreign/nested IDs, privilege/owner injection,
missing/invalid CSRF, ZIP/XXE/XSS/path payloads, лимиты/гонки/сбои storage и409.
`make check`, Docker IT и CI должны проходить; runtime JAR не содержит H2/test
fixtures, secrets/env/исходные книги не входят в Git/images. Данные для приёмки
синтетические либо с разрешённой лицензией, внешние DB/SMTP не используются.

Согласование этой спецификации не закрывает функциональные задачи и не означает
production-ready сейчас. Оно фиксирует конечный объём курсовой и критерии,
которые предстоит доказать без деплоя.
