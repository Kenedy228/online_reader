# Чтение EPUB и TXT

Владелец открывает READY-книгу кнопкой «Читать книгу» в библиотеке или карточке.
Читалка использует Spring MVC/Thymeleaf и GET-навигацию без JavaScript:
оглавление EPUB, предыдущий/следующий фрагмент, переход между главами,
три размера текста. TXT представляет одну главу. Форматы и ограничения —
[mvp.md](mvp.md), приём исходников — [book-files.md](book-files.md).

## Позиция

`GET /library/books/{id}/read` принимает `chapter`, `offset`, `fingerprint`,
`version`, `font` и необязательный `anchor` из оглавления EPUB.
Начальный запрос может не содержать locator; продолжение использует SHA-256
неизменяемого исходника, `version=1`, ключ главы и смещение в Unicode code points.
Ключ TXT — `text`, EPUB — `s0`, `s1`, … в порядке spine исходника. Номер страницы,
размер шрифта и ширина экрана в позицию не входят. Размер фрагмента — не более
16 384 code points; ссылки оглавления используют fragment id, затем преобразуют
его в смещение. Отсутствующий anchor и выход за диапазон отклоняются.

Для TXT начальный BOM игнорируется, CRLF/CR нормализуются в LF. Для XHTML
скрытые поддеревья исключаются, пробельные последовательности вне `pre`
схлопываются, границы блоков разделены LF. Подписи изображений и сообщения о
неподдерживаемом медиа входят в текст и его смещения. Разрешённые атрибуты
`data-offset` отмечают начала сегментов реконструированной разметки.
При изменении этих правил нужна новая версия представления и явная стратегия
для сохранённых позиций. Не меняйте нормализацию незаметно для #25/#26.

Метаданные книги не меняют locator. Замены исходника на месте нет: другой
исходник загружается отдельной книгой. Несовпадение fingerprint/версии даёт 409.
Перед разбором сервер проверяет фактический SHA-256, включая случай изменения
байтов без изменения размера. Хэш клиента никогда не разрешает доступ.
Сохранение прогресса между сеансами, revision/debounce и restore реализованы
в [progress.md](progress.md); личные заметки реализованы в [notes.md](notes.md). Позицию также можно сохранить
адресом страницы. Bare reader URL восстанавливает progress, явный locator имеет приоритет.

## Граница доверия и ресурсы

Каждый запрос страницы и изображения проходит `FileBookTransactions.download`:
CurrentAccount проверяет живой аккаунт, SQL выбирает только его READY-книгу до
обращения к storage. Администратор также читает только собственные книги.
Неизвестная и чужая книга дают одинаковый 404. В SecurityConfig зарегистрированы
только GET/HEAD read/resources; fallback denyAll, CSRF и CSP сохранены.

Исходный XHTML не вставляется в HTML приложения. StAX запрещает DTD, entities,
внешний resolver и XInclude; глубина ограничена 128, атрибуты/namespace — 64.
Сервер экранирует текст и создаёт только фиксированные теги заголовков, абзацев,
списков и выделения; исходные атрибуты, CSS, JS и URLs не копируются.
Внешние ссылки остаются текстом, внешние изображения — подписями; сетевых
запросов к ресурсам книги нет. SVG, script/style, forms, frames, objects и MathML
не исполняются. Шрифты книги не выдаются, DRM не поддерживается.

`GET /library/books/{id}/resources/{index}?fingerprint=…&version=1` выдаёт только
PNG/JPEG из manifest. Index назначает сервер; URL не принимает ZIP/FS path.
Проверяются реальный ImageIO format и размеры ≤8192 по стороне/16 MP, затем
поток выдаётся как image/png или image/jpeg, inline, nosniff и no-store.
Полная проверка декодирования изображения выполнена при загрузке, исходник
неизменяем и повторно проверяется по SHA-256. Нет перекодирования изображения
в потенциально больший bitmap/PNG. Оригинал по-прежнему скачивается отдельным
attachment endpoint. Private resources не добавляются в public allowlist.

## Ограничения обработки и ошибки

Страницы: два параллельных разбора, без очереди, кооперативный deadline 10 с.
Изображения: два активных потока, максимум восемь ожидающих, ожидание ≤1 с.
Read pin удерживается до закрытия ZIP/потока; cleanup не удаляет активный файл.
HEAD закрывает поток без тела. Прерывания и ошибки освобождают pin и permit.

Исходник ≤10 МиБ, ZIP ≤2000 entries, один entry ≤8 МиБ, суммарное чтение entries
для страницы ≤32 МиБ, ratio ≤100. Приватные каталоги не распаковываются, кэша
книг/HTML нет. Текст выбранной главы ограничен 8 МиБ UTF-16 units; оформление
сохраняется для первых 256 разрешённых элементов выбранного фрагмента, изображения — первых 128 в нём.
В пределах фрагмента далее весь текст и подписи сохраняются без оформления/bitmap;
ранние главы/фрагменты не расходуют бюджет последующих. Пустая глава сохраняет
оглавление и переходы, не объявляя всю книгу повреждённой. Пустые теги не
раздувают ответ; если сгенерированная разметка превышает 256 КиБ символов,
фрагмент возвращается экранированным текстом. Лимит 16 384 относится к тексту
книги, а не к навигации; оглавление ограничено 2000 ссылками/200 code points.

Некорректный диапазон/параметры — 400; недоступная книга/файл/изображение — 404;
другая версия позиции — 409; повреждённый источник — 422; занятость — 503 с
Retry-After. Тексты ошибок фиксированы, не отражают ввод, пути или исключения.
Потеря права аккаунта сохраняет действующий 403, анонимный UI-запрос — login
redirect. Поток, оборвавшийся после начала ответа, закрывается без дописывания
исключений в тело. Стандартные HTTP security headers остаются включены.

## Проверка

`make check` включает Unicode/TXT, EPUB2 NCX/EPUB3 nav, безопасную разметку,
лимиты/XXE, query encoding, MVC owner/Admin/flags/state, MIME/cache и lifecycle
read pins. HTTP upload tests проверяют открытие принятого TXT/EPUB в читалке.
PostgreSQL/SMTP-проверки запускаются отдельно `make test-integration`.
Изменения представления требуют regression checks и браузерного прохода:
чтение/TOC/фрагменты/шрифт, локальные изображения, клавиатура/видимый focus,
320 px, текст 200%, accessibility и отсутствие внешних запросов.
Автоматическая проверка не заменяет ручной screen reader и измерение p95 из #27.
